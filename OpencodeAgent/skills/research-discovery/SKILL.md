# Research Discovery — 先确定研究什么

## 实验边界与优先级

本分支先显式试用，不自动接管所有开放问题。用户调用本 skill 或明确要求“先探索需求 / 先选研究路线”后，本会话的相关研究使用本协议；退出探索后回到原流程。

启用时，本协议优先于 AGENTS、intake、research-scenarios 中“开放型默认执行”“最多一轮三问”“固定 T-1”和强制推荐附加分析的旧规则。intake 仅负责已经选定路线的参数补全；不再重新默认市场、持仓或风险。财务数据溯源、账户权限、只读与禁止自动下单的规则始终有效。

这是交互政策和可验证 brief，不是安全沙箱或运行时授权门。未通过运行时准入实验前，不宣称模型无法绕过它。

## 工作流

1. 读当前对话、已有 brief 和用户修订；保留用户原话，识别他想作出的判断，而不是先匹配工具名称。
2. 区分“学习概念 / 找候选 / 诊断已有持仓 / 验证规则 / 解释事件”。明确查询或完整回测直接执行其已请求范围，不再征求同一授权。
3. 维护当前目标、已知约束、未知项和决策依赖。只展开当前研究相关的分支，不构造整套投资规划问卷。
4. 按下节选择必要问题，或先给用户可区分的研究路线。读取 [能力路线](routes.md)，以 [recipes.json](recipes.json) 编译工具计划；目录与标的解析可以先做。
5. 用户选择后总结目标、产物验收、排除范围和成本范围，再补全执行参数。回答改变目标时更新 revision、撤销旧路线许可，不延续已过期计划。
6. 多步骤执行复用 VT `research-goal` skill 和现有目标/证据台账；不要创建第二个金融任务数据库。真实会话 ID 须由客户端提供；拿不到时说明无法保证跨会话恢复，不让模型编造 ID。
7. 只执行选定组合。用实际结果和来源核验验收条件；回测收益差是有效结果，不自动调优。证据不足、数据失败、取消分别说明，不能伪装完成。

## 按决策依赖提问

- **渐进模式（默认）**：只问答案会改变路线、成本、必要证据或持仓风险解释的问题。独立且易答的可以合并；依赖未决答案的问题留到后续轮。不要凑“提出3个问题”。
- **深度模式（用户选择）**：进一步挖掘当前目标相关的取舍、失败条件、替代假设和验收标准；不要求遍历所有分支。
- 每个问题解释“回答它会改变什么”，允许自由文本、“不知道 / 先看示例 / 跳过 / 我有其他想法”。不要把偏好包装成推荐答案诱导用户全选“是”。
- 能查到的事实由工具查，例如标的身份、财报日期、数据覆盖。成本价、真实仓位、资金用途、用户偏好不能从市场数据推断。
- 不知道或跳过保留 `source=unknown,value=null`；不等于空仓、A股或稳健。可以提供用户选定的非个性化研究或标注假设的教学示例。
- 停止条件：路线可选定、关键执行边界清楚、产物验收可表达；**不以固定三问/一轮为停止条件**。用户随时可结束或继续深挖。
- 无新增信息时不复读：总结已知与未决，提供轻量示例、改目标或暂缓的出口。
- 使用主 agent 原生 question（若客户端支持）；IM 用文本选项等待真实回复。cron/headless 只执行既有明确计划，新开放任务生成待选择摘要并暂停，不自动跑昂贵分析。

## 路线呈现与许可

只展示当前问题相关的少量路线，不总是三条。每条说明：能回答什么、输入、增量证据、成本类别、市场覆盖、不能证明什么；用户选的是研究目标，不是 tools 名字。

“最近市场涨很多，还能买吗？”可以区分：

- 判断回撤风险：技术形态；A股还可看已验证的微观逃顶信号。
- 验证买入规则：先看真实策略目录和证据，再回测选定规则。
- 检验多空论据：用户选择后由适合该目标的 VT swarm 做多视角评审。

如果用户补充“我满仓 NVDA，担心财报”，改为持仓风险与事件研究；不继续全市场选股。

低成本目录、必要标的解析可以先执行。全市场扫描、批量回测、策略改写、swarm、周期执行仅在用户明确请求/选择的范围内执行；“深度探索”本身不授权这些动作。“你看着办”也不授权账户读取、下单或无限优化。路线变化后重新确认新增成本。

## brief v2 与参数编译

契约：[brief.schema.json](brief.schema.json)。用 `intake_version="2.0"` 与递增 revision；历史 intake v1 fixture 不改写。

- `constraints` 保留 user/tool/default/unknown 来源及原因；用户偏好不默认，真正采用的教学假设写入 assumptions。
- `market` 使用 `a/us/crypto`；仅跨市场配置比较使用 `cross`，逐来源核实覆盖，不把它传入单市场工具。数据研究 ready 前必须明确市场，纯策略目录允许未知；取消时清空 tool_plan 与 approval。
- 分开投资期限 `investment_horizon`、研究样本 `sample_start/sample_end`、`warmup_bars`、频率、基准与成本模型；禁止把三个月投资期限机械编成三个月回测。
- `routes` 与 `selected_route` 引用 recipe ID；`decisions` 记录问题依赖、答案与来源；`acceptance_criteria` 与 `out_of_scope` 定义验收和不做什么。
- `approval` 只记录真实用户消息引用与 revision，**不是授权证明**；模型填一个消息 ID 或 confirmed 字段不构成可信确认。客户端须对照真实事件，否则仅是待审核计划。
- `tool_plan[].args` 是真实 MCP 实参。`backtest` 只有 `run_dir`；config 放在 `files[]` 的 `kind=config`、`path=<run_dir>/config.json`、`content` 中，信号代码按 VT 契约另写。不得给 backtest 传 config。
- 参数以当前 `tools/list.inputSchema` 为准，工具还须通过当前 deny 清单；目录存在不等于配置允许、数据可用或证据合格。
- 由镜像内 `brief_validation.py` 校验；v2 必须提供完整工具 schema 和权限清单，不用旧 summary-only 快照。校验成功只说明契约合法，不代表文件已生成、市场可用或用户已授权。

## 结果与下一步

研究产物保留目标、实际假设、来源、数据覆盖、限制和具体下一步；选择题/brief 不算研究产物。根据证据缺口推荐下一步，不强制推广全部因子、swarm 或报告导出。

日期写每个来源真实的 data_as_of；混合实时与历史数据分别标注，不能统一写 T-1。回测继续返回 run_id、结构化结果和控制面 Run Detail，不新增 HTML 产品路径。

风险预算是验收阈值，不因调用 risk 函数就算满足；必须比较实际工具指标。swarm 观点不等于策略收益证据；策略目录不等于已验证推荐。
