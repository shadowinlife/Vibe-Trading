# intake — 澄清与收敛协议

> 本 skill 是开放型 / 待澄清型请求的**唯一**澄清来源。协议目标：**多做事，少提问；一次问清，绝不复读**。

## 触发条件
满足任一条件即加载本 skill：
1. 无明确标的，寻求机会/推荐（"明天买什么""最近有什么机会"）；
2. 场景明确但缺关键槽位，且缺失项属于用户私有信息（"我持有的科创ETF如何解套""我的持仓怎么样"）；
3. 槽位值未知，且该值**无法由工具解析**；
4. 用户回答"不知道 / 不确定 / 随便 / 你看着办"。

## 分流边界
先判定请求类型，再决定是否加载本 skill。四类路由表（AGENTS.md 保留同一张表，澄清细节在本 skill）：

| 类型 | 判定标准 | 分支 |
|------|---------|------|
| **明确可执行** | 标的明确（或可用工具解析）+ 动作明确 + 存在可直接映射的能力 | 直接执行，默认不提问 |
| **开放型** | 无明确标的，寻求机会/推荐（"明天买什么""最近有什么机会"） | Least-to-Most 收敛漏斗（一轮） |
| **待澄清型** | 场景明确但缺关键槽位，且缺失项属于用户私有信息（"我持有的科创ETF如何解套"） | 槽位澄清（一轮） |
| **宏观型** | 宏观事件/地缘政治/自然现象，传导链长、超出市场数据可直接回答的范围（"俄乌战争对后续市场影响"） | Step-Back 协议 |

- **明确可执行 不加载本 skill**：ACT by default，按「能力索引」直接路由；有合理默认值时一句话声明假设后执行；**能用工具解决的歧义绝不问用户**（标的 → `search_symbol`；估值口径 → `ch_describe_table` 查 COMMENT；行业归属 → `get_sector_info`）。
- **宏观型 不加载本 skill**：Step-Back 协议，完整步骤见 `research-scenarios` 场景 F。
- 分类本身不向用户展示；分类后立即执行对应分支。

## 漏斗维度
开放型按序收敛：**市场 → 工具类型（股票/ETF/可转债）→ 期限 → 风险预算（最大回撤容忍）→ 风格（价值/成长/动量/红利）→ 候选池规模**。

从漏斗中挑出对当前请求**区分度最高**的维度提问，其余维度取默认值并在执行时一句话声明。

## 槽位澄清规则
槽位清单：**标的识别 / 成本价 / 仓位规模 / 持有期限 / 风险承受**。

1. **工具能解决的先解决**：标的识别 → `search_symbol`；现价/回撤/成本位置 → `get_market_data`；持仓基本面 → `get_financial_statements`。这些**不问用户**。
2. **只问用户私有槽位**：成本价、仓位规模、持有期限、风险承受。市场、工具类型、期限、风险预算、风格、候选池规模属于可默认槽位（见「漏斗维度」），不进入提问。
3. 用户拒绝提供私有槽位时，用情景假设代替（"按成本价=现价下方 10% 的常见套牢深度演示"），明示假设后继续。
4. 收敛后路由：选股需求 → `research-scenarios` 场景 E；单一机会/配置需求 → 场景 A/B；持仓诊断 → 场景 A（标的分析）+ `risk-analysis`（仓位/回撤约束）。

## 分层轮次预算
- **默认一轮**：每个意图最多 1 轮澄清，单轮 **≤3 问**，编号列表批量提出。
- **追加轮（唯一例外）**：仅当用户对某个问题**明确回答"不知道 / 不确定"**时，才允许追加 1 轮，且**只问该槽位**（最多再 1 问）。
- 除此之外**绝不重复问第二轮**：发起第二轮以上的提问属于协议违规 —— 应切换为"最合理解释 + 明示假设 + 邀请纠正"；第三次提问在任何情况下都不允许。
- 澄清问题必须带选项与后果描述；开放式追问（"你具体想怎样？"）视为低质量提问，尽量避免。

## 逃生门
每个问题必须包含逃生门选项：**"以上都不是 / 我有其他想法"**。用户选择逃生门时不追加提问，改为按用户补充的内容重新分流。

## 参数编译规则
用户选中的选项**编译为工具参数**，而不是原样塞进提示词：

| 选项 | 编译目标 |
|------|---------|
| 稳健型 / 平衡型 / 激进型 | 回测与筛选的最大回撤约束（如 ≤15% / ≤25% / ≤40%） |
| 价值 / 成长 / 动量 / 红利 | 筛选因子（估值分位 vs 营收增速 vs 动量 vs 股息率） |
| 候选池规模 Top 5 / Top 10 / Top 20 | 筛选结果条数 |
| 期限 1 个月 / 3 个月 / 1 年 | 回测区间、监控窗口、年化口径 |

默认值同样以参数形式落到工具调用里，并在输出中用一句话声明（"以下按 A 股、近 3 年、稳健档、Top 10 假设执行"）。

## 执行承诺
1. 一轮（或允许的追加轮）结束后**立即执行**，不再等用户确认：按最合理解释 + 明示默认值执行，并邀请用户纠正（"以下按 X 假设执行，如需调整请指出"）。
2. 用户拒绝提供私有槽位 → 用默认值 + 情景假设执行，并在输出开头列出假设。
3. 执行后必须给出具名产物（个股体检 / 选股清单 / 组合体检 / 事件影响 等），不得只回一段解释或反问。
4. 产物正文结尾必须附四行 closing block（我假设了什么 / 换一个会怎样 / 下一步能做什么 / `仅供研究，不构成投资建议；数据截止 T-1。`）。它是**产物的结尾，不是产物的替代**：不得只给 closing block 而不给产物，纯解释性回答（如"什么是因子"）不附。四行模板见 `research-scenarios` 的「产物结尾契约」章节。
5. 非交互会话（cron / headless `opencode run` / IM）不得调用 question；改用文本选择题或直接用默认值执行。

- 与 VT `load_skill`（`vibe-trading_load_skill`，91 个金融 skill）是**两套系统**：不要尝试用 VT 工具加载本文件，也不要指望它出现在 `vibe-trading_list_skills` 的结果里。
- 非交互会话（cron / IM / `opencode run`）不得依赖交互式提问；无法提问时直接按上述默认值执行。
